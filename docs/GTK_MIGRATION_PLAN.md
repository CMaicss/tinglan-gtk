# Tinglan：GTK4 + libadwaita 前端迁移计划

- 本地项目建立：2026-11-20（UTC+8）。用途：从 `CMaicss/tinglan-gtk` fork 迁移桌面 UI，保留上游音源生态与本地用户数据。
- 计划基线：`main` / `e09c99d`。此文是方案，不代表实现、测试或发布。
- 本 fork 只发布 Linux：`.deb`、`.rpm`、`.AppImage`（将“Application”按 AppImage 理解）。首版建议 x86_64，以 GNOME/Wayland 为主要验收环境，另做 X11 冒烟。

## 改动边界

- 可改：`native/cmd/music/` 的前端渲染、表现状态、窗口和系统控件适配及测试；必要时新增独立 GTK UI 包和资源。Go 依赖只增补 GTK 所需部分、移除已确认没有 Linux 引用的平台依赖，不升级共享依赖。另允许调整 Linux 应用打包、发行 CI、包元数据及对应文档，不扩到其他工具或业务逻辑。历史 `docs/VIVA_MIGRATION.md` 保留。
- 不改：音源插件协议、清单及能力声明，华为插件入口，Linux 的登录、播放、媒体控制、歌词与资源解析、存储和数据库、`appmeta`，以及 `cmd/music` 内的共享业务行为。即使兼容标识里有 `viva` 也不重命名。
- 本 fork 不支持 macOS/Windows，可删除其专用源码、测试、平台依赖、打包脚本、CI 目标及现行支持文档。删除按实际构建约束和调用关系判断，不能仅按文件名匹配；共享文件只清理已不再使用的平台分支，不改 Linux 行为。平台清理与 GTK 迁移分开提交，方便同步上游和定位回归；不改插件对外协议或删除已有发布资产。
- 目标是只保留 GTK 前端，不维护 Viva 兼容入口。迁移期暂用 `linux && gtk` 标签；按页面和功能迁出仍与 Viva 混在一起的共享方法，GTK 实现和对应回归通过后删除旧视图。GTK 达到功能等价后移除 Viva 入口、专用探针和工具、依赖及现行文档中的构建说明；旧版对照从基线提交取，不复制业务层。标识或加密上下文里包含 `viva` 的兼容常量不属于清理对象。
- 将 GTK 视图、资源和 Linux 打包各自集中到独立目录，与共享代码只做少量接线。GTK 前端、Linux 发行与文档分别成组；同步上游时先跑原业务与插件回归，再跑 GTK 验收。除约定的前端接线、依赖和发行路径外，与上游的差异不应扩大。

## 实施顺序

1. **打通构建和线程模型。** 在容器里验证 Go（基线声明 `1.27.3`）、cgo、GTK4/libadwaita 开发包，优先评估 gotk4 与 gotk4-adwaita，锁定能在目标发行版上编译运行的一组版本，并核对所用绑定包的许可证。先跑起 `AdwApplication` / `AdwApplicationWindow`，验证事件调度、退出清理和跨前端 profile 单写者。宿主 `pkg-config` 当前未找到 GTK4/libadwaita，不能据此推断容器里的构建结果。
2. **先跑通一个音源的完整链路。** 用 GTK 文件选择器、确认弹窗和音源设置页接现有入口；用原样测试插件验证 ZIP/目录安装 → 启用/握手 → 搜索 → 播放 → 重启恢复。覆盖不支持的能力、授权取消、插件启动失败/超时与错误显示。先验这个链路，再迁其余页面。
3. **迁移其余界面和交互。** 用 Adwaita 原生导航、标题栏和设置页；长列表用 GTK 列表模型，保留搜索分页、点歌加入而非替换队列、收藏总数、导入歌单只读语义；补详情、历史、播放条、队列、逐字/翻译歌词、试听提示和外观设置。字体排版与图标使用 GTK/Pango 和现有资源；旧 Viva 视觉参数确实无法等价映射时显式记录，不重置旧设置。不追求玻璃效果逐像素一致。
4. **回归后再切换。** 保留原 Go 测试和旧前端的回归入口；为 GTK 增加离线交互测试和隔离 profile 验证。两套前端按顺序打开同一份合成 profile，核对已启用音源、会话、曲库、收藏和队列；然后在 GNOME/Wayland 实测输入法、文件选择、窗口行为、隐藏后续播及 MPRIS。最后更新前端文档，如实区分编译、离线回归、实机与真账号验证。

## 界面与流畅性验收

- 以 [GNOME HIG](https://developer.gnome.org/hig/guidelines/adaptive.html) 为准：宽窗使用原生侧栏，窄窗收起导航但保留返回入口；底部常驻播放控制，队列按需打开，让封面和歌词成为视觉重点。跟随系统明暗、对比度和动画偏好；优先使用原生控件、语义颜色和 symbolic 图标，CSS 限于少量品牌细节，不搬运玻璃特效。验收高 DPI、键盘焦点、中文输入法、空白/加载/错误状态。
- 用 GTK `ListView` / `GridView` 回收列表项，按批次更新数据；封面按显示尺寸异步加载与解码，限制并发和缓存，快滚或切页取消过时任务。进度条和歌词局部刷新；后台继续处理播放事件，但窗口不可见时不做动画或整窗重绘。
- 同一设备、同一合成 profile 记录 Viva 与 GTK 的冷启动至可交互、长列表滚动帧间隔（p95）、搜索输入至界面反馈（不含网络）、后台 CPU 和 RSS。测 10,000 首曲库、边播边滚、快速切页及反复打开歌词。60 Hz 环境以约 16.7 ms 帧预算为优化目标，具体门槛在基线测出后冻结，不用容器或无头截图替代真实 GNOME/Wayland 验收。

## Linux 打包与流水线

- 当前 `.github/workflows/native-checks.yml` 的目标规划、检查 runner 和 Release 汇总都绑定 macOS/Windows。迁移时只替换发行目标及必要的 CI 接线；保留 PR 检查门槛、手动构建只产 artifacts、发布门槛和校验文件。发布前校验三种格式齐全；插件按 Linux 架构只生成一套 ZIP，不随三种应用包重复构建。优先复用 `tinglan-tool plugins` 的本机目标、筛选逻辑及现有命名，不改插件打包契约。
- `.deb` / `.rpm` 使用各发行版的运行库依赖，安装桌面入口、图标与 AppStream 元数据。`.AppImage` 单独验证运行库打包：按 [AppImage 官方建议](https://docs.appimage.org/reference/best-practices.html) 选兼容构建基线，在干净的目标系统实测 GTK/libadwaita、图标和资源加载，不承诺通吃所有发行版。开发和流水线构建走容器，桌面实测走真实会话。
- 三种成品分别验证启动、播放、音源装载、升级后读回原 profile；`.deb` / `.rpm` 验证卸载不删除用户数据。任何格式未过实测，不列为已支持。

## 发布前的兼容门槛

- 测试插件必须无需重打包、改 manifest、改协议或重新安装即可复用；与原版一样，二进制插件需要匹配 OS/架构，脚本插件需要原有运行时。至少使用仓库已有合成示例和华为同平台插件，区别离线握手/种子会话与真实登录；不使用私人凭据或做真实账号写入，扫码与线上播放另经授权验收。
- 已有会话仍有效时不要求重新登录；已过期会话继续按原策略处理。已存在的曲库、设置、插件授权与播放队列不引入新格式、不搬迁目录。若验证出核心层必须改，先停下来说明原因，不扩范围补丁。
- 用变更清单对照基线检查受保护路径零差异；未完成插件与 profile 回归，不宣称“无缝”，不切默认、不发布。
