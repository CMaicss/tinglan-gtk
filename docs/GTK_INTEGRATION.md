# GTK 功能接入 · 第一阶段（2026-11-20）

用途：验证原生 GTK 入口复用现有 Go 模型。仅 Linux、可选 `gtk` 构建标签，默认仍为 Viva。这个入口尚无完整 UI 功能，不用它替换日常客户端或打开正在使用的 profile。预览稿 `docs/ui-preview/` 暂保留用于对照，等正式 GTK 前端验收后可删除。

## 设计稿直连 Go

从仓库根执行 `./out/native/tinglan`。Linux 可执行文件内嵌 `native/cmd/music/designui/` 的界面与资源，无需从 docs 执行脚本，也不依赖启动目录。窗口使用已有 Go 模型，不启动网络服务；默认复用当前原生 profile，先检查单实例锁。旧客户端仍在运行时请先退出。

封面与歌词操作、收藏和歌单编辑、音源与设置均已接入同一设计稿窗口。Go 的音乐、歌词与插件测试及 10 项 GTK 控件测试通过；构建和 Go 测试仍使用临时 `webauth` 编译覆盖。整合版入口为 `out/native/tinglan`，已在本机用当前华为会话验证真实收藏、搜索结果点播和 PipeWire 输出。`--smoke` 会使用真实账号并正常更新当前队列和历史，只用于明确授权的实测。新增写入操作主要以临时库和插件夹具验证；真实封面、宽窄窗对照、发布入口和旧 UI 清理仍需完成。

## 本机验收：旧 GTK 整合版

- 使用隔离的原生 profile **副本**在 GNOME/Wayland 启动，复用已登记的华为音源并恢复现有会话，不重新授权。从收藏实际点播，进度推进，PipeWire 确认对应进程的音频流未静音、未暂停，送到当前蓝牙输出。确认可进出歌词并暂停；未验证重新授权或华为搜索结果点播。
- 用实际 GTK 客户端离线对照定稿：宽窗全高侧栏约 205 px，播放键 44 × 44；修正隐藏页面撑宽窗口后，400 × 680 的收藏、歌单、音源设置和歌词能完整显示。1920 × 1080 歌词页封面和歌词分列，400 px 堆叠，当前句用正常前景色加粗，播控不重复曲目信息。离线歌单卡片仍用符号占位，不作等同定稿的声明。
- 整合版窗口回归：离线搜索入队、重启恢复、队列选曲／移除／清空、隐藏窗口续播通过；音乐、歌词和插件 Go 测试通过。仍需补齐发行、正常构建和其余视觉状态验收。

## 第一阶段记录

- 搜索复用原音源选择逻辑、请求取消、代际过滤和分页；选择结果仍走原入队逻辑，不替换队列。上一首、播放/暂停、下一首、进度定位复用原 Go 方法。
- GTK 运行在锁定的 OS 主线程。后台 goroutine 只投递结果并请求 GLib 唤醒；同时至多一个待执行源，关闭时取消。隐藏窗口时 Go 状态照常推进，不更新不可见控件。列表回收 GTK 行组件，分页只追加，不重建已有列表。
- 队列面板复用旧版选曲、移除和确认清空的操作逻辑，面板关闭时不构建行快照。面板打开时只在队列代际变化后检查行差异，未改变的行不重新写入 GTK。
- 播放历史只展示现有本机记录，GTK 不额外请求远端历史；页面可见且记录版本变化时才同步。搜索点歌仍插入队列，历史点歌仍以历史列表启动播放。已用合成音频在实际 GTK 窗口验证两种行为和最终保存的队列。
- 未接：完整曲库和歌单界面、歌词、音源选择及管理界面、外观、托盘、最终响应式布局。真实账号兼容和桌面性能仍待验收。

## 构建与验证

空 profile 的搜索已用实际 GTK 窗口验证：未启用音源时提示「没有可搜索的音源」，而非崩溃或误报「未找到结果」。插件宿主的离线测试覆盖了示例插件握手和搜索（临时 `sources/` 返回两首）、华为插件进程外运行与种子会话读取、启用状态恢复。容器内测试会自行调用 `go build` 构建插件；临时构建参数须通过 `GOFLAGS` 传给子进程。

Viva 不作为长期兼容入口；等 GTK 覆盖并验证原功能后，删除旧前端及其专用依赖。旧测试中验证业务行为的用例迁到共享层，不随 UI 一起删除。

容器内可用 `python3 scripts/check-gtk-search.py /tmp/tinglan-gtk` 跑 Xvfb + xdotool 冒烟。该脚本用临时 profile 预置两首，驱动真实 GTK 窗口搜索和点歌，再重启、搜索并加入第二首，断言原曲目及顺序不变；还验证队列选曲、移除、取消和确认清空。

用 `python3 scripts/check-gtk-background.py /tmp/tinglan-gtk` 验证窗口隐藏后自动切歌。脚本自行生成合成音频、临时 ALSA null 配置并启用隔离 Xvfb，不依赖容器声卡。

在带 Go 1.27.3、C 编译器、pkg-config、GTK4 / libadwaita 开发包的 Linux 容器里，从 `native/` 执行。基线 Linux 编译会卡在 `internal/webauth/browser_other.go` 的未定义变量 `attempt`；同样影响 Viva。未经确认不改这一仓库文件，需先修复基线才能常规构建。

```sh
go build -tags gtk -o /tmp/tinglan-gtk ./cmd/music
/tmp/tinglan-gtk --demo 10000
```

`--demo` 不读取默认用户 profile。`--check-background --demo 2 --fixture-dir <目录>` 用自制 `tone.mp3` / `tone.flac` 检查隐藏后是否推进到第二首，无需音源或账号。在无声卡的容器中，可将 `ALSA_CONFIG_PATH` 指向仅含 `pcm.!default { type null }` 的临时配置。已在临时 Go overlay（只将误写的 `attempt` 改为 `flow`）、Xvfb 和 ALSA null 环境下构建并通过隐藏窗口切歌测试；调度器通过 `-race`。这不代表真实声卡、登录或 GNOME/Wayland 验收。
